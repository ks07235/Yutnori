# Yutnori 개발 현황과 인수인계

최종 갱신: 2026-10-15 (한국 시간)

## 필수 협업 규칙: GitHub 푸시와 사용자 보고

이 문서는 **모든 로컬과 모든 작업자가 작업 시작 전에 가장 먼저 읽는 기준 문서**다. 아래 규칙은 선택 사항이 아니다.

1. GitHub에 소스를 푸시하기 전에 이 문서의 `작업 이력`과 현재 버전·검증 상태를 반드시 함께 갱신한다. 코드만 푸시하고 문서를 나중에 보완하지 않는다.
2. 작업 이력에는 `일시(KST) / 작업자와 로컬 / 버전과 빌드 / 작업 종류 / 변경 내용 / 검증과 산출물 / 브랜치와 커밋`을 남긴다.
3. 아직 완성하지 않았거나 푸시하지 않은 변경은 완료 이력에 섞지 말고 `현재 진행 중`에 명시한다. 다른 로컬 변경을 추측해서 완료로 기록하지 않는다.
4. 실제 버전은 `app/build.gradle.kts`에서, 검증 숫자는 생성된 테스트·lint 결과에서 확인한다. 기억이나 파일 이름만으로 적지 않는다.
5. 코드 커밋 후 짧은 해시를 확인하고 문서 이력에 기록한 다음, 문서 커밋까지 포함해 같은 푸시에 올린다. 문서만 변경한 푸시도 이력에 `문서` 작업으로 남긴다.
6. 푸시가 끝나면 사용자에게 아래 형식으로 반드시 보고한다. 성공 여부를 말하지 않고 작업을 종료하지 않는다.

```text
GitHub 푸시 완료
- 일시(KST):
- 브랜치 / 커밋:
- 버전 / 빌드:
- 올라간 내용:
- 검증 결과:
- APK·AAB 등 산출물과 경로:
- 푸시에 포함하지 않은 변경 / 남은 작업:
```

7. 보고 내용은 실제 `git status`, 원격 브랜치, 커밋과 파일을 확인한 결과만 사용한다. AAB·APK를 만들지 않았거나 Drive 동기화를 확인하지 못했다면 그대로 밝힌다.
8. 다른 로컬의 변경, 사용자 파일, 복구 자료를 임의로 삭제하거나 강제 푸시하지 않는다. 충돌이 있으면 보존한 뒤 사용자에게 알린다.

## 개발을 이어가기 전에

1. 이 문서를 먼저 읽고 `git status`로 기존 로컬 변경을 확인한다. 다른 사람이 남긴 변경이나 복구 자료를 지우지 않는다.
2. 현재 배포 기준 브랜치는 `main`이다. 작업을 시작하기 전에 원격 `main`과 로컬 HEAD를 비교한다.
3. 원격 `main`을 fetch하고 로컬 HEAD와 비교한다. 로컬 변경이 있으면 보존한 뒤 진행하며 강제 푸시하지 않는다.
4. 실제 버전은 `app/build.gradle.kts`의 `versionName` / `versionCode`로 확인한다. 파일을 이름만 바꿔도 내부 버전은 바뀌지 않는다.
5. UI는 가로·세로, 시간 제한전·무제한전, 휴대폰·태블릿을 함께 확인한다. 이번 가로 변경을 세로에 적용하지 않는다.
6. 개발 후 이 문서의 최신 상태·검증 결과·남은 확인 항목도 함께 갱신한다. AAB 또는 APK 전달과 GitHub 소스 반영을 모두 수행한다.
